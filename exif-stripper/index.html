What is hidden inside a photo file

A JPEG is not just a picture. It is a container: the compressed image sits in one part, and around it the camera or phone wrote a series of tags describing when the photo was taken, with what, on which settings, and — most people's surprise — exactly where. That block is EXIF, and a modern phone fills it generously: make and model, the lens, focal length, aperture, shutter speed, ISO, whether the flash fired, the date and time down to the second, the software version, and often a tiny thumbnail of the original image that survives crops and edits.

With location services on, the file also carries GPS latitude and longitude, sometimes with altitude and direction. A screenshot carries nothing, which creates a false sense of security: the photos people worry about are exactly the ones with GPS in them, and they look identical in every file browser and photo app preview.

Alongside EXIF there may be XMP, which records edit history and sometimes the original filename, and IPTC fields used by newsrooms for captions and credits. PNG files can hold text chunks with anything in them. All of this travels with the file when you email it, put it in a listing, upload it to a marketplace, attach it to a job application or send it to a stranger who asked for "a photo of the damage".

Who can read it, and what it costs you

Anyone with the file. There are dozens of free EXIF viewers that turn a photo into a map pin, and social networks, marketplaces and messaging apps index and store the original uploads. The realistic risks are mundane rather than dramatic:

  • Selling online. A photo of an item on your kitchen table, with GPS, tells a buyer where the item is and when you are likely to be home.
  • Posting family photos. A picture of a child at a park carries the park's coordinates and the exact minute it was taken.
  • Forums, reviews and job applications. The camera model and serial-number-like maker notes can tie two anonymous accounts to the same person.
  • Dating and social apps. The platform usually strips metadata from the copy it publishes, but the original in a direct message may not be stripped at all.

None of this means every photo needs stripping. It means the choice should be yours, made with the knowledge of what is in the file, rather than a default you never saw.

How this stripper works

When a file lands on the page, the browser reads it into memory as bytes and this page walks the container structure — JPEG segments, PNG chunks, WebP chunks — to find the metadata blocks and report what they contain. That is the read-only half, and it never modifies the original.

The clean copy comes from a different route. The browser decodes the image into pixels, the pixels are drawn onto an HTML canvas, and the canvas is encoded back into a brand-new file. A canvas has no place to store EXIF: it knows only width, height and colour values, so the new file is built from pixels and nothing else. The metadata is not deleted from a block list; it simply never exists in the output. That is why the result is reliably clean across formats instead of depending on which tags a script remembered to remove.

The trade-off is re-encoding. JPEG is lossy, so decoding and re-encoding at quality 0.92 changes the bytes slightly even though the picture looks identical. Set the quality to 1.0 for a near-lossless pass, or export as PNG when the file will be edited again — PNG output is larger but exact. The orientation tag is also lost, which is why the page applies it to the pixels first: a photo taken sideways still appears upright after stripping, because the rotation is baked into the image instead of being described in a tag.

Worked example: a used-laptop listing

What a normal phone photo reveals

You photograph a laptop on your desk and upload it to a marketplace. The file is a 3.2 MB JPEG from a phone. Its EXIF block names the phone model, the exact capture time, and a GPS position accurate to a few metres — the desk. The embedded thumbnail shows a wider view of the room than the cropped photo you uploaded.

Run it through this page and the report lists the camera, the timestamp, "GPS location — yes, hidden in the file", and a 12 KB embedded preview. Download the clean copy: the same photo, 2.1 MB, with no location, no camera, no timestamp and no thumbnail. Nobody looking at the listing learns anything about the desk.

Worked example: before and after, in numbers

What changes on disk

A 4,032 × 3,024 phone JPEG at 3.4 MB with a 14 KB EXIF block, an ICC profile and a maker-notes segment becomes a 4,032 × 3,024 JPEG at quality 0.92, around 2.2 MB, with no metadata at all. The pixel dimensions are identical and the image looks the same on screen; the file is smaller because the recompression is slightly more aggressive than the camera's and the extra blocks are gone.

Choose "scale to 2048 px" and the same photo comes out at 2,048 × 1,536 and about 600 KB — plenty for a marketplace listing, and another reason not to upload the original.

Lossless removal, and when it is the better choice

Some tools strip metadata without re-encoding, by rewriting the container and dropping the metadata segments. The pixels are untouched, so there is no generation loss at all, and a JPEG can even get smaller without any change in quality. The catch is that such tools only remove the blocks they know about, and a strange maker-notes segment or an unexpected XMP packet can survive if the code does not recognise it.

A canvas re-encode is the blunt instrument: everything that is not a pixel is gone, in every format, every time. For most people that reliability is worth the tiny recompression, especially at quality 0.92 or above where the difference is invisible. If you are archiving originals for later editing, keep the untouched file and strip a copy.

Frequently asked questions

Are my photos really never uploaded?

Correct. View the page source: there is no form action, no fetch to a server and no third-party script. The file is read with the browser's FileReader API, drawn to a canvas and encoded in the same tab. You can confirm it by disconnecting from the internet after the page loads and processing a photo anyway.

Does stripping metadata change how the photo looks?

Not at quality 0.92 or above — the difference is below what a screen or a print can show. Two things do change: the orientation tag is replaced by actually rotating the pixels, and the camera's colour profile is replaced by the browser's plain sRGB one, so an image shot in a wide-gamut space can shift slightly in colour. If colour accuracy matters, export PNG and convert the profile in an editor afterwards.

Can I remove metadata from a video?

Not here. Video containers (MP4, MOV) need a different remuxing step, and browsers cannot re-encode them reliably in a page. For video, use a desktop tool such as ffmpeg with -map_metadata -1.

Why does my iPhone photo fail?

Because it is HEIC, a format browsers cannot decode. On iOS, Settings → Camera → Formats → Most Compatible makes new photos JPEG. For existing ones, share the photo through an app that converts it, or export it from Photos to Files as JPEG, then run it here.

Is the GPS really removed, or just hidden?

Removed. The output file is built from pixel values only, so there is no field left to hold a coordinate. You can verify by dropping the clean file back onto this page — it will report no EXIF and no GPS, because the scanner is reading the same bytes a stranger would.

Do social platforms strip metadata for me?

Most strip it from the copy they serve, which is why a photo posted publicly usually shows no GPS when downloaded. That protection ends at the platform's edge: the original you email, attach to a listing or send in a message still carries everything. Strip first if the file is going anywhere you do not control end to end.

Before you post

Look at what the report says before you decide. A screenshot with no metadata needs nothing. A phone photo of a stranger's house, a child, or an item you are selling should lose its GPS. And if you keep the original for your own archive, keep it on your own device rather than in a shared folder — the clean copy is the one that travels.

This tool removes metadata from the copy you download. It cannot remove a file already published elsewhere, and it does not audit what a platform does with the files you give it. Verify the clean copy by running it through the page again if it matters.
